ESILV-Bot  
ESILV Smart Assistant – Multi-PDF RAG Chatbot

## 1. Overview

ESILV-Bot is a domain-specific assistant for ESILV, built on a mono-turn Retrieval-Augmented Generation (RAG) pipeline and exposed through a Streamlit chat interface.
It uses several official ESILV PDFs (brochure, MSc, bachelors, apprenticeship, pedagogical booklet), which are ingested, chunked, and indexed into a vector store, then queried by a local LLM (via Ollama/Mistral) through a Retriever and a QA Generator.

## 2. Project structure

Main logical layout of the repo:

- `data/`  
  - ESILV source PDFs: `esilv_brochure.pdf`, `esilv-msc.pdf`, `bachelors-esilv.pdf`, `plaquette_apprentissage_esilv.pdf`, `livret_pedagogique_esilv.pdf`  
  - `esilv_documents.txt`: merged text generated by `pdf_loader.py`  
- `notebooks/`  
  - Agent testing, retrieval evaluation, accuracy/latency analysis  
- `src/`  
  - `ingestion/`  
    - `pdf_loader.py`: multi-PDF extraction → `esilv_documents.txt`  
    - `chunker.py`: text chunking and metadata enrichment  
    - `indexer.py`: indexing into ChromaDB  
  - `agents/`  
    - `retriever.py`: retrieval agent (top‑k search, scoring, filtering)  
    - `qa_generator.py`: QA agent generating answers conditioned on retrieved context  
  - `core/`  
    - `workflow.py`: mono-turn orchestration (Retriever → QA)  
  - `ui/`  
    - `app.py`: full-screen Streamlit chat application  
- `logs/`: ingestion / workflow / agents logs  
- `requirements.txt`: Python dependencies  

## 3. Installation

1) Clone the repository and move into it:

```bash
git clone https://github.com/AlexandreFrancony/ESILV-Bot.git
cd ESILV-Bot
```

2) Create and activate a virtual environment:

```bash
python -m venv venv
# Linux / macOS
source venv/bin/activate
# Windows
venv\Scripts\activate
```

1) Install dependencies:

```bash
pip install -r requirements.txt
```

If something goes wrong, delete the `venv/` folder and repeat the steps above to get a clean environment.

## 4. Data ingestion pipeline

All ESILV PDFs must be placed in the `data/` folder with the names expected by `pdf_loader.py` (or you can update the `PDF_FILES` list in that script).

Whenever you add or update PDFs, rebuild the data and index with:

```bash
# 1. Extract text from all PDFs → data/esilv_documents.txt
python src/ingestion/pdf_loader.py

# 2. Chunk text + add metadata → intermediate files / vectorstore input
python src/ingestion/chunker.py

# 3. Index chunks into ChromaDB
python src/ingestion/indexer.py   # answer 'n' if asked to reset everything
```

These three scripts must be run again every time the source documents change so the vector index stays in sync.

## 5. Running the applications

### 5.1. CLI workflow test

To test the RAG pipeline without the UI:

```bash
python -m src.core.workflow
```

This starts an interactive loop in the terminal where you can ask questions and see both the answer and the associated sources.

### 5.2. Streamlit chat app

The main user interface lives in `src/ui/app.py`.

From the project root:  

```bash
python -m streamlit run src/ui/app.py
```

Main UI behaviour:

- Conversation history stored in `st.session_state.messages` (user / assistant messages)  
- Each user input triggers `run_workflow(question)` from `src.core.workflow`  
- The assistant’s answer is displayed along with the list of sources and their similarity scores
